Реализовано чтение элемента `<description>` из FB2 через `xml.etree.ElementTree` в новом модуле `fb2_parser.py` (структуры берутся из `fb2_structures.py`). Проверено на тестовом файле `test_book.fb2` — все проверки прошли.

## С какого элемента начинать парсер

Разбор FB2 удобно строить сверху вниз по реальной вложенности документа:

1. **Корень `<FictionBook>`** — `parse_xml(path)` (см. `fb2_xml.py`; модуль
   вырезает DTD, чтобы исключить «XML-бомбы»).
2. **Первый смысловой элемент `<description>`** — его и стоит писать первым, потому что он:
   - идёт в схеме сразу после необязательных `<stylesheet>`;
   - самодостаточен (метаданные книги не зависят от основного текста);
   - не требует рекурсивного обхода `section`/`body`.
3. **Внутри `<description>` — `<title-info>`** (обязательный, всегда первый), затем `<document-info>`, `<publish-info>`, `<custom-info>`, `<output>`.

То есть начинать нужно с `<description>`, а внутри него — с `<title-info>`.

## Как реализовано чтение

- **Пространства имён.** Элементы FB2 лежат в `NS_FB`, поэтому имена для поиска — `"{http://www.gribuser.ru/xml/fictionbook/2.0}description"`. Так как часть реальных FB2 идёт **без `xmlns`**, сделаны хелперы `_find`/`_findall` с фолбэком на имя без namespace.
- **Атрибуты с префиксами.** `xml:lang` → `"{http://www.w3.org/XML/1998/namespace}lang"`, `xlink:href` → `"{http://www.w3.org/1999/xlink}href"`.
- **Точки входа:**
  - `parse_description(source)` — принимает путь к файлу, file-like объект или готовый `ET.Element` (корень), возвращает `Description`.
  - `parse_description_element(elem)` — разбирает уже найденный узел `<description>`.
- **Сопоставление по схеме:** `title-info`→`TitleInfo`, `document-info`→`DocumentInfo`, `publish-info`→`PublishInfo`, `custom-info`→`CustomInfo`; жанры (`genre@match`, по умолчанию 100), авторы, серии (`sequence` с вложенностью), обложка (`inlineImageType`), даты (`date@value`), разметка внутри `<annotation>` (`styleType` → `StyleNode`).
- **CLI:** `python fb2_parser.py book.fb2` выводит метаданные.

## Важная тонкость ElementTree

Нельзя писать `elem.find(a) or elem.find(b)`: у элемента **без дочерних узлов** булево значение равно `False`, поэтому валидный результат терялся (и появлялся `DeprecationWarning`). Проверка делается строго через `is None` — это исправлено в `_find`/`_findall`.

## Целочисленные идентификаторы заголовков

Заголовкам присваиваются целочисленные идентификаторы (`heading_id`/`parent_id` в `Section` и `Body`). Метод `Fb2Parser.assign_heading_ids(bodies)` вызывается автоматически из `parse_bodies`, но доступен и напрямую.

- **Заголовок** — любой `<body>` или `<section>`, у которого есть `<title>`.
- `heading_id` — сквозной номер заголовка, начиная с 1, в порядке обхода документа (уникален в пределах книги, включая все `<body>`).
- `parent_id` — номер ближайшего заголовка-предка; `None`, если такого предка нет. Для `<body>` всегда `None`.
- Секции **без** `<title>` собственного номера не получают (`heading_id is None`), но им всё равно записывается `parent_id` предка — это позволяет привязывать их текст к родительскому заголовку.

Метод возвращает последний использованный номер (0, если заголовков нет). Флаги `with_ids` у `describe_bodies`/`describe_section_tree` включают вывод номеров (полезно для отладки).
