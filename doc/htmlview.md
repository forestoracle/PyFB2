# Можно ли сделать во FreePascal из визуального компонента THTMLView просмотрщик Markdown? Реализация пока не нужна, нужен совет

Да, это возможно, но с одной важной оговоркой: **THTMLView не понимает Markdown — ему нужно скормить HTML**. То есть просмотрщик строится по схеме «Markdown → HTML → THTMLView». Ниже — разбор по пунктам.

## Ключевая схема

```
Markdown-файл → (ваш конвертер MD→HTML) → HTML-строка → THTMLView.LoadFromString(html)
```

THTMLView — это по сути браузерный движок для подмножества HTML 3.2/4, поэтому задача сводится к написанию **конвертера Markdown в HTML** (аналогично тому, как в проекте уже есть `fb2_markdown.pas` — только в обратную сторону, как `markdown_to_fb2`).

Что покрыть в конвертере:
- блоки: `#…######` → `<h1>…<h6>`, абзацы → `<p>`, `> цитата` → `<blockquote>`, списки → `<ul>/<ol>/<li>`, ```` ```code``` ```` → `<pre>`, `---` → `<hr>`, таблицы → `<table>`;
- inline: `**b**`→`<b>`, `*i*`→`<i>`, `~~s~~`→`<strike>`, `` `c` ``→`<code>`, `[t](url)`→`<a>`, `![alt](src)`→`<img>`.

Это, кстати, ложится ровно на тот же блок-парсер, что вы уже разбирали в `markdown_to_fb2` — просто целевой формат не структуры FB2, а HTML-строка.

## Подводные камни именно THTMLView

1. **Кодировка — главный риск.** Классический THTMLView (порт thtmlviewer от Д. Гурьянова) исторически ANSI. Для русского текста в UTF-8 это критично. Варианты:
   - взять **юникодную версию/форк** (`TUniHTMLViewer` и подобные для Lazarus);
   - либо отдавать контент в нужной кодировке и выставлять `Charset`/заголовок `<meta http-equiv="Content-Type">`.
   Это стоит проверить первым делом — иначе кириллица «поедет».

2. **CSS почти не поддерживается.** Не рассчитывайте на стилизацию Markdown через CSS (типографика цитат, отступы, фоны). Всё оформление — только через теги: `<h1>…<h6>`, `<b>`, `<i>`, `<blockquote>`, `<pre>`, `<font color=…>`, атрибуты таблиц (`border`, `cellpadding`).

3. **Картинки.** Поддерживаются, но набор форматов зависит от сборки: PNG в старых версиях требует отдельного модуля. Нужно задавать базовый путь (`Base`/`OnImageRequest`), иначе относительные `![](images/…)` не найдутся.

4. **Нет JS.** Поэтому подход «подключить marked.js и рендерить в движке» здесь не работает — это аргумент в пользу WebView (см. ниже).

5. **Нет подсветки синтаксиса кода** — максимум `<pre>` + `<font>`.

## Когда THTMLView — хороший выбор, а когда нет

| Критерий | THTMLView | WebView (WebView2 / WebKitGTK / CEF4Delphi) |
|---|---|---|
| Внешние зависимости | нет (лёгкий) | есть (Edge/WebKit/Chromium) |
| CSS/стилизация | почти нет | полноценно |
| UTF-8/кириллица | нужен юникод-форк | из коробки |
| Markdown | нужен свой конвертер MD→HTML | можно рендерить JS-библиотекой (marked.js) без конвертера |
| Подсветка кода, footnotes, task lists | нет | да |

## Рекомендация

- **Если цель — лёгкий офлайн-просмотрщик с базовым форматированием** (заголовки, жирный/курсив, списки, цитаты, таблицы, картинки) и без внешних зависимостей — да, THTMLView вполне подойдёт. Делайте модуль `md_to_html.pas` (block + inline парсер, по образцу вашего `fb2_markdown.pas`) и грузите результат через `LoadFromString`. Обязательно решите вопрос с юникодом.
- **Если хочется «как в браузере»** (CSS, красивые цитаты/код, подсветка, ссылки с якорями) — берите WebView. На Windows это **WebView2** (Edge, есть в системе), на Linux — **WebKitGTK**, кроссплатформенно — **CEF4Delphi**. Тогда конвертер MD→HTML вообще не нужен: HTML собирается и рендерится на стороне JS.

Дополнительный совет по интеграции с вашим проектом: раз уже есть `fb2_parser.pas`, можно сделать **два** режима просмотра — «Markdown» (MD→HTML→THTMLView) и «FB2 напрямую» (FB2→HTML→THTMLView), минуя Markdown. Это часто удобнее, чем гонять книгу через Markdown ради просмотра.

Итог: **технически да, реализуемо**, ключевая работа — конвертер MD→HTML, а главные грабли — кодировка и отсутствие CSS в THTMLView. Если готовы на внешнюю зависимость ради качества — WebView сэкономит и время, и нервы.
