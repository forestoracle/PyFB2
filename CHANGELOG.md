# История изменений

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии — по [семантическому версионированию](https://semver.org/lang/ru/).

## [Unreleased]

### Исправлено
- **FB2 → DOCX/EPUB/HTML/MOBI/ODT**: заголовок `<title>`, состоящий из
  нескольких `<p>` (разные строки), больше не склеивается без разделителя —
  строки соединяются пробелом (в DOCX/EPUB/HTML — один заголовок со строками
  через пробел; в MOBI/ODT — один `<hN>`/`<text:h>` вместо нескольких).
  Затронуты `fb2_to_docx.py`, `fb2_to_epub.py`, `fb2_to_html.py`,
  `fb2_to_mobi.py`, `fb2_to_odt.py` и их Pascal-порты; добавлен тест
  `test_roundtrip.py::test_multiline_title_not_merged`.
- **CLI (Pascal)**: `fb2html_cli` и `fb2markdown_cli` теперь используют явно
  заданный выходной файл (2-й аргумент) и каталог изображений (3-й) — раньше
  из-за условия `ParamCount > 2` / `> 3` эти аргументы игнорировались.
- **EPUB → FB2**: разделы FB2 теперь строятся по оглавлению EPUB
  (`nav.xhtml` для EPUB3 либо `toc.ncx` для EPUB2), а не только по
  заголовкам `<h1>`–`<h6>` в XHTML. Раньше при отсутствии заголовков
  получался один безымянный `<section>` (оглавление терялось), а при
  наличии «служебных» заголовков (титульный лист и т. п.) оглавление
  засорялось лишними разделами. Заголовки, дублирующие название раздела из
  оглавления, пропускаются; вложенные заголовки дают подсекции.
  Дополнительно: пустые секции (в т. ч. только с изображением) получают
  `<empty-line>` — вывод снова валиден по XSD; `<date value>` пишется
  только для полной даты `ГГГГ-ММ-ДД`; названия разделов из NCX очищаются от
  сносочного маркера « *» и лишних пробелов. Затронуты `epub_to_fb2.py` и
  Pascal-порт `epub_to_fb2.pas`; добавлены тесты в `test_epub3.py`.
- **EPUB → FB2**: текст книги больше не теряется, если EPUB (собранный из FB2
  сторонним конвертером, например FB2EPUB) заворачивает блочное содержимое
  главы в `<span>`: такие «обёртки» теперь обходятся как контейнер, иначе
  получался FB2 с оглавлением, но без текста. Дополнительно:
  документы `spine` без записи в оглавлении распределяются по порядку
  чтения — продолжения глав (документ разбит на несколько XHTML) дописываются
  в текущую секцию, а документы после последнего раздела (сноски, приложения)
  образуют завершающую секцию; заголовок секции, продублированный в тексте
  (`<div class="title1"><p>Глава 1</p><p>КТО СУДЬИ…</p></div>`) не повторяется;
  пустой `<p/>` (`<p class="empty-line"/>`) превращается в `<empty-line>`.
  Затронуты `epub_to_fb2.py` и Pascal-порт `epub_to_fb2.pas`; добавлены тесты
  в `test_epub3.py`.


### Добавлено
- **GUI: прогресс загрузки больших книг.** `TFb2ToHtmlConverter.OnProgress`
  отдаёт 0..100 по этапам (чтение/разбор XML, отрисовка секций, выгрузка
  картинок); `TFb2Viewer.OnLoadProgress` / `AddLoadProgressListener` сообщают
  этап (`TFb2LoadStage`) и процент, `ProcessMessagesOnLoad` опционально
  прокачивает сообщения между этапами. `TFb2StatusBar` четвёртую панель теперь
  рисует как полосу прогресса: во время загрузки — прогресс загрузки, после —
  прогресс чтения; панель обновляется через `Invalidate`+`Update`, поэтому
  видна и при синхронной загрузке в главном потоке.

- **Архивы FB2** — новые модули `fb2_zip.py` (`FB2Zip`) и `fb2_unzip.py`
  (`FB2Unzip`), включённые в пакет: упаковка книг в «однокнижные» ZIP-архивы
  (`book.fb2.zip`) и распаковка архивов (извлекаются только записи `.fb2`,
  остальные игнорируются). Есть атомарная запись архива, защита от «Zip Slip»
  (`os.path.commonpath` + нормализация регистра), удаление исходников
  (`remove_source`), пропуск существующих архивов (`overwrite`), предпросмотр
  (`dry_run`), обработка файла или каталога (рекурсивно, с сохранением
  структуры через `out_dir`). Диагностика — через `logging`
  (`pyFB2.fb2_zip` / `pyFB2.fb2_unzip`), результат — `Fb2ZipResult` /
  `Fb2UnzipResult`; классы и результаты экспортируются из `pyFB2`.
  Новые подкоманды `pyfb2 zip` / `pyfb2 unzip` (всего 16) и console-scripts
  `pyfb2-zip` / `pyfb2-unzip`; тесты — `tests/test_zip_unzip.py`.

- **Порт на FreePascal** (`pas/`): портирован конвертер **Markdown → FB2** —
  `markdown_to_fb2.pas` (`TMarkdownToFb2Converter`): разбор Markdown
  (заголовки `#`/`##`/…, метаданные `**Автор:**`/`**Жанры:**`/`**Дата:**`/
  `**Язык:**`, цитаты `>`, таблицы `| … |`, стихи, изображения из файлов →
  `<binary>`) и inline-разметка (`**жирный**`, `*курсив*`, `~~зачёркнутый~~`,
  `` `код` ``, `<sub>`/`<sup>`, ссылки, картинки); сборка `TFictionBook` и
  сериализация через `TFb2Writer`. Сопоставление жанров — через
  `fb2_genres` (`GenreCodeExists`/`GenreCodeByName`, исправлен на
  `WideLowerCase` для кириллицы). CLI — `markdowntofb2_cli`; обновлены
  `Makefile` и `build_pascal.bat`. Проверено round-trip FB2 → Markdown
  (`fb2markdown_cli`) → FB2 и кросс-совместимость с Python (одинаковая
  структура для метаданных, жанров, обложки и изображений).

- **Порт на FreePascal** (`pas/`): портирована пара конвертеров **FB2 ↔ MOBI**
  (Mobipocket/Kindle KF7): `fb2_to_mobi.pas` (`TFb2ToMobiConverter`) —
  разметка текста простым HTML (Mobi7), сжатие PalmDOC (LZ77), упаковка в базу
  данных Palm (PalmDOC/MOBI/EXTH-заголовки, обложка через EXTH
  coveroffset/thumboffset) и `mobi_to_fb2.pas` (`TMobiToFb2Converter`) —
  разбор PDB, распаковка PalmDOC, встраивание изображений (`recindex` → data
  URI) и разбор HTML через `html_to_fb2`; метаданные (заголовок, авторы,
  жанры, язык, обложка) восстанавливаются из EXTH. CLI — `fb2tomobi_cli`,
  `mobitofb2_cli`; обновлены `Makefile` и `build_pascal.bat`. Проверено:
  round-trip FB2 → MOBI → FB2, байт-в-байт совпадение текстовых и
  графических записей с Python-версией (кроме случайного UID) и
  кросс-разбор MOBI обеими реализациями.

- **Порт на FreePascal** (`pas/`): портирован конвертер **HTML → FB2** —
  `html_to_fb2.pas` (`THtmlToFb2Converter`): собственный толерантный
  HTML-парсер (аналог HTMLParser, декодирование сущностей), сборка
  `TFictionBook` (заголовок/автор/жанры/обложка/аннотация из
  `<header class="book-header">`, иерархия секций по `<h1>`-`<h6>`, абзацы,
  разметка, цитаты/эпиграфы, стихи, таблицы, изображения из файлов и
  data-URI) и сериализация через `TFb2Writer`. CLI — `htmltofb2_cli`;
  обновлены `Makefile` и `build_pascal.bat`. Проверено round-trip
  FB2 → HTML (`fb2html_cli`) → FB2 и кросс-совместимость с Python (тот же HTML
  разбирается обеими реализациями).

- **Порт на FreePascal** (`pas/`): портированы конвертеры **FB2 ↔ ODT** —
  `fb2_to_odt.pas` (`TFb2ToOdtConverter`: ODF 1.2 ZIP с `mimetype` без сжатия,
  `META-INF/manifest.xml`, `content.xml`, `styles.xml`, `meta.xml`, изображения
  `Pictures/*`; заголовки `text:h`, автоматические текстовые стили, таблицы,
  картинки `draw:frame`) и `odt_to_fb2.pas` (`TOdtToFb2Converter`: чтение ODF
  через `TEpubArchive`, разбор DOM-парсером fcl-xml, стек секций по
  `text:outline-level`, стили span, таблицы, изображения → `<binary>`). CLI —
  `fb2toodt_cli` и `odttofb2_cli`; обновлены `Makefile` и `build_pascal.bat`.
  Проверено round-trip `test.fb2` и кросс-совместимость с Python (ODT-архивы
  совпадают по составу и размерам записей; Pascal читает ODT из Python и
  наоборот).

- **Порт на FreePascal** (`pas/`): портированы конвертеры **FB2 ↔ DOCX** —
  `fb2_to_docx.pas` (`TFb2ToDocxConverter`: OOXML-архив ZIP с
  `[Content_Types].xml`, `_rels/.rels`, `word/document.xml`, `word/styles.xml`,
  `word/_rels/document.xml.rels`, `docProps/core.xml`, `docProps/app.xml`,
  изображения `word/media/*`; заголовки HeadingN, таблицы, гиперссылки,
  DrawingML-картинки) и `docx_to_fb2.pas` (`TDocxToFb2Converter`: чтение
  OOXML через `TEpubArchive`, разбор DOM-парсером fcl-xml, стили HeadingN ->
  иерархия секций, таблицы, изображения -> `<binary>`, сопоставление жанров
  через `fb2_genres`). CLI — `fb2todocx_cli` и `docxtofb2_cli`; обновлены
  `Makefile` и `build_pascal.bat`. Проверено round-trip `test.fb2` и
  кросс-совместимость с Python (сгенерированный DOCX совпадает с Python
  по составу и размерам записей; Pascal читает DOCX из Python и наоборот).

- **Порт на FreePascal** (`pas/`): портированы конвертеры **FB2 ↔ FB3** —
  `fb2_to_fb3.pas` (`TFb2ToFb3Converter`: OPC-контейнер ZIP с
  `[Content_Types].xml`, `_rels/.rels`, `fb3/description.xml`, `fb3/body.xml`,
  `fb3/meta/core.xml`, связи `*.rels` и изображения `fb3/img/*`; UUID для секций

  через `TEpubArchive`, разбор частей DOM-парсером fcl-xml, сборка
  `TFictionBook`). CLI — `fb2tofb3_cli` и `fb3tofb2_cli`; обновлены `Makefile`
  и `build_pascal.bat`. Проверено round-trip `test.fb2` и кросс-совместимость с
  Python-версией (Pascal читает FB3 из Python и наоборот).

- **GUI: `TFb2Outline` и `TFb2FileTreeView` — свойство `Visible` в `published`.**
  У `TFb2Outline` (наследник `TCustomTreeView`, где `Visible` объявлено только
  `public`) свойство переопубликовано — теперь его можно задавать в инспекторе
  объектов и в `.lfm` (скрывать/показывать дерево). У `TFb2FileTreeView`
  (наследник `TShellTreeView`, где `Visible` уже `published`) свойство указано
  явно — для наглядности и единообразия с остальными компонентами.

- **Порт на FreePascal** (`pas/`): конвертер **FB2 → HTML** (`fb2_html.pas`,
  класс `TFb2ToHtmlConverter`) и CLI `fb2html_cli` — оглавление, двусторонние
  ссылки сносок, режим data-URI (`InlineImages`), встроенный CSS; обновлены
  `Makefile`, `build_pascal.bat`, `README_PASCAL.md`. Вывод совпадает с
  Python-версией по составу тегов, атрибутов, якорей и ссылок. Плюс
  опциональный GUI-пакет Lazarus **`fb2viewer.lpk`** (вкладка «FB2»):
  `fb2viewer.pas` (`TFb2Viewer` — просмотр FB2 на `THtmlViewer`),
  `fb2outline.pas` (`TFb2Outline` — дерево заголовков на `TTreeView` с
  навигацией) и `fb2viewer_reg.pas` (регистрация); заметка —
  `doc/fb2_viewer.md`. Конвертер `fb2_html.pas` получил потоковый вход
  (`ConvertStream`/`WriteStream`) и `BinaryByFilename`; `TFb2Viewer.LoadFromStream`
  грузит книгу без временного каталога (картинки — из памяти через
  `OnImageRequest`).
- **Порт на FreePascal** (`pas/`, продолжение): портированы библиотечные
  утилиты — `fb2_errors.pas` (иерархия `EFb2Error`), `fb2_files.pas`
  (инфраструктура обхода каталогов, чтения/записи), `fb2_encoding_scanner.pas`
  (поиск каталогов с разными кодировками), `fb2_author_scanner.pas` (поиск
  каталогов с разными авторами), `fb2_transcoder.pas` (перекодировка FB2 в
  UTF-8), `fb2_renamer.pas` и `fb2_group_renamer.pas` (переименование по
  шаблону). Модули собраны и проверены на временном дереве FB2.
- **Порт на FreePascal** (`pas/`, продолжение): портирован **SQLite-индекс
  библиотеки** — `fb2_index.pas` (класс `TFb2Index`: схема `books`/`authors`/
  `titles`/`genres`/`author_facts`/`book_text`, инкрементальный обход по
  size/mtime, поиск по метаданным через SQL-функцию `fb2_norm` — регистро- и
  ё-независимо, полнотекстовый поиск FTS5 с ранжированием BM25 и сниппетами) и
  CLI `fb2index_cli` (build/stats/authors/books/search/find/dups). Проверено на
  дереве FB2: добавление, пропуск без изменений, поиск по автору/тексту, дубли
  по SHA-1. Для работы требуется `sqlite3.dll`; FTS5 берётся из той же
  библиотеки (при её отсутствии полнотекстовый поиск отключается).
- **Порт на FreePascal** (`pas/`, продолжение): портирован **`fb2_split_merge`** —
  `fb2_split_merge.pas` (классы `TFb2Splitter`: разбиение по секциям, размеру
  или на N частей с обновлением `<title-info>`/`<document-info>` и копированием
  только используемых `<binary>`; `TFb2Merger`: слияние книг с объединением
  авторов/жанров, единым `<body>` и разрешением конфликтов `id` у `<binary>` с
  перепривязкой ссылок) и CLI `fb2splitmerge_cli` (подкоманды `split`/`merge`).
  `copy.deepcopy` заменён явными функциями клонирования структур. Проверено на
  реальной книге: разбиение в трёх режимах, повторный разбор части, слияние
  частей и слияние книги с самой собой (дубли `<binary>` получают суффикс `_N`).
- **Порт на FreePascal** (`pas/`, продолжение): портирован **`fb2_normalizer`** —
  `fb2_normalizer.pas` (класс `TFb2Normalizer`: приведение к UTF-8, порядок
  элементов по XSD, добавление обязательных полей, удаление дубликатов
  `<binary>` и битых `<image>`, схлопывание пробелов, отчёт о правках
  `TNormalizationResult`) и CLI `fb2normalizer_cli`. Вместо lxml — fcl-xml;
  восстановление XML ограничено экранированием «голых» `&`, проверка по XSD
  недоступна (в fcl-xml нет валидатора). Проверено на «грязном» файле (1251,
  CRLF, неправильный порядок, дубликаты `<binary>`, лишние пробелы — 9 правок)
  и на реальной книге (идемпотентность: повторная нормализация даёт 0 правок,
  переводы строк — LF).
- **Порт на FreePascal** (`pas/`, продолжение): начат перенос конвертеров.
  Добавлены `fb2_images.pas` (тип, расширение и размеры изображений —
  `DetectImageType`, `ImageSize`, `ScaleToWidth`; нужен конвертерам в
  контейнерные форматы) и `fb2_to_txt.pas` (`TFb2ToTxtConverter` — экспорт в
  обычный текст: метаданные, заголовки, абзацы, эпиграфы/цитаты, стихи,
  таблицы, заглушки изображений, оглавление) с CLI `fb2txt_cli`. Вывод TXT
  побайтово совпал с Python-версией; попутно найден важный нюанс — Pascal
  `Trim` не снимает NBSP, поэтому добавлен Python-совместимый `PyStrip`.
- **Порт на FreePascal** (`pas/`, продолжение): портирован конвертер в EPUB —
  `fb2_to_epub.pas` (класс `TFb2ToEpubConverter`: `TEpubBook`/`TEpubDocument`/
  `TEpubResource`, OPF 2.0 и 3.0, `toc.ncx`, `nav.xhtml`, `style.css`,
  XHTML по секциям, обложка, изображения) и CLI `fb2epub_cli` (`--epub3`).
  ZIP собирается через `TZipper` (paszlib), `mimetype` кладётся первым и без
  сжатия. Проверено на реальной книге: 36 записей архива, имена и порядок
  совпадают с Python, 35 записей побайтово идентичны; единственное отличие
  (2 байта в `content.opf`) — fcl-xml отбрасывает пробельные текстовые узлы,
  которые lxml сохраняет. Попутно выяснено: `zbase` из paszlib экспортирует
  значение `COPY` (enum `inflate_codes_mode`), перекрывающее встроенный
  `Copy`, поэтому подключать его нельзя — нужен `zstream`.
- **Порт на FreePascal** (`pas/`, продолжение): портирован обратный конвертер
  `epub_to_fb2.pas` (класс `TEpubToFb2Converter`) + два вспомогательных
  юнита: `fb2_archive.pas` (чтение ZIP в память через `TUnZipper` с
  `OnCreateStream`/`OnDoneStream` — без распаковки на диск) и
  `fb2_genres.pas` (справочник из 110 жанров, сгенерирован из
  `resources/genres.json`). Поддерживаются EPUB 2.0 и 3.0: container.xml →
  OPF, dc-метаданные, манифест, изображения → `<binary>`, обложка, обход
  spine с иерархией секций по h1–h6, таблицы, списки, pre/hr/figure,
  инлайн-разметка. CLI `fb2fromepub_cli`. Проверено на реальной книге:
  результат совпадает с Python построчно (3434 строки), все 7 бинарников
  побайтово идентичны; остаются только различия сериализации
  `fb2_writer.pas` (префикс `xlink` против `l`, порядок атрибутов, пробел
  перед `/>`) — они общие для всего вывода писателя и не влияют на XML-смысл.
  Попутно выяснено: fcl-xml НЕ заполняет `NamespaceURI`/`Prefix`/`LocalName`
  (они пусты), поэтому пространство имён Dublin Core определяется по
  `NodeName` вида `dc:title`.
- **GUI: компонент `TFb2ViewerToolbar`** (`pas/fb2viewertoolbar.pas`,
  наследник `TToolBar`) — панель читалки поверх уже готового `TFb2Viewer`:
  назад/вперёд по истории (`HistoryIndex`, доступность по `OnHistoryChange`
  движка), в начало, размер шрифта (`DefFontSize` + `Font.Size` с перерисовкой
  и сохранением позиции), поиск (`TFindDialog` + `FindEx`, вперёд/назад,
  регистр), копирование, печать (`TPrintDialog` + `TvwPrinter`) и
  `PrintPreview` в `TMetaFilePrinter`. Кнопки собираются по набору `Commands`,
  состояние — через событие `OnStateChange`.
- **GUI: доработки `TFb2Viewer`.** Добавлен `ReRender` (перерисовка текущего
  документа без повторного разбора FB2 — нужна для смены размера шрифта) и
  множественная подписка `AddDocumentLoadListener` /
  `RemoveDocumentLoadListener`; `TFb2Outline` и `TFb2ViewerToolbar` теперь
  используют её и не перекрывают друг другу `OnDocumentLoad`.

### Безопасность
- Защита от «XML-бомб» (`billion laughs`): `xml.etree.ElementTree` раскрывает
  сущности из внутреннего подмножества DTD, поэтому перед разбором объявление
  `<!DOCTYPE ...>` вырезается (объявить сущности без DTD невозможно). На
  `fb2_xml` переведены `fb2_parser`, `fb2_split_merge`, `fb2_web_metadata`,
  конвертеры (`fb2_to_html/markdown/pdf/txt`, `epub_to_fb2`, `docx_to_fb2`).
  Обычные FB2 с `<!DOCTYPE FictionBook SYSTEM "FictionBook.dtd">` читаются
  как раньше.
- `fb2_normalizer`: проверка результата по XSD выполняется парсером
  с `resolve_entities=False`/`no_network=True`.

  «Логирование».
- **GUI: `TFb2Viewer` и `TFb2Outline` — переопубликованы `Align` и `Anchors`.**
  Унаследованные от «Custom»-базовых классов (`TCustomPanel`/`TCustomTreeView`)
  эти свойства были только `public` (доступны в коде, но не видны в инспекторе
  объектов Lazarus). Теперь они в `published`-секции компонентов — задаются на
  этапе дизайна и сохраняются в `.lfm`. Поведение в рантайме не изменилось.

### Исправлено
- **`TFb2Outline` не перестраивался при загрузке новой книги.** Дерево решало,
  «тот же это документ или новый», сравнивая **указатель** конвертера
  (`FViewer.Converter = FLastConverter`), а `TFb2Viewer.LoadFromFile`
  освобождает и создаёт конвертер заново — аллокатор возвращает тот же адрес
  (проверено: `FreeAndNil` + `Create` дают тот же указатель), поэтому новый
  документ выглядел как прежний и оглавление оставалось от предыдущей книги.
  В `TFb2Viewer` добавлен счётчик документа `DocumentSerial` (растёт при каждой
  загрузке), и `TFb2Outline` сравнивает его. Та же замена сделана во внутреннем
  кэше позиций заголовков (`TocPositionsValid`), страдавшем тем же дефектом.
- `fb2_writer`: атрибут ``type`` у ссылок (``<a type="note" l:href="#…">``)
  больше не теряется при сериализации — сноски и другие типизированные
  ссылки переживают round-trip «структуры → XML».
- `fb2_parser`: текст внутри `<td><p>…</p></td>` (ячейка таблицы с абзацем —
  частый вариант в реальных файлах) больше не теряется: новый
  `_parse_cell_markup` переносит содержимое вложенных блоков, поэтому
  таблицы перестали быть пустыми и в DOCX/ODT-экспорте, и в индексе.
- `FB2Renamer`: ошибки чтения/разбора FB2 теперь поднимаются как `RuntimeError`
  с понятным сообщением (раньше наружу летел необработанный `ParseError`).
- `FB2GroupRenamer.rename_all`: повреждённый FB2-файл больше не прерывает
  групповое переименование — ошибка сообщается, остальные файлы обрабатываются.
- `FB2Renamer`: в шаблоне `outdir` разделители каталогов (`/`, `\`) больше не
  удаляются — работает вложенная раскладка вида `${Al}/${S}`.
- `fb2_to_pdf`: внутренние ссылки (сноски вида ``<a l:href="#n_1">``) больше
  не роняют сборку PDF с ошибкой «format not resolved, probably missing URL
  scheme or undefined destination target». Для секций с ``id`` теперь
  регистрируются именованные назначения (``<a name="…"/>``), внутренние
  ссылки на них становятся кликабельными, а ссылка на отсутствующую цель
  выводится обычным текстом.
- **GUI: `TFb2Outline` не подсвечивал текущую главу при прокрутке.** Причина —
  `TFb2Viewer.AnchorPosition` использовал публичное `THtmlViewer.IDControl[]`,
  а оно возвращает объект только для элементов форм (`TFormControlObj`) и
  картинок (`TImageObj`); для текстовых якорей заголовков (`<hN id="sec-N">`)
  всегда `nil`, поэтому позиции всех глав были `-1` и слежение не срабатывало.
  Теперь объект берётся из `THtmlViewer.NameList` (это `IDNameList` движка) с
  чтением `YPosition` — так же, как сам движок делает в `PositionTo`. Заодно
  кэш позиций якорей сбрасывается при изменении высоты документа (асинхронная
  подгрузка картинок, изменение размера окна), чтобы `Y` заголовков не
  «уезжали».
- **Потеря иллюстраций при `normalize`/`rewrite`.** Блочные `<image>` внутри
  `<section>`/`<body>` терялись: парсер складывал все `<image>` секции в одно
  поле `Section.image` (перезапись — выживала только последняя), а
  `Fb2Writer._build_section`/`_build_body` это поле вообще не выводили. В
  реальной книге (525 иллюстраций) после обработки оставалась только обложка.
  Теперь парсер читает «главную» картинку секции в `Section.image`, а все
  остальные — блочным контентом (`Section.content`); писатель выводит `image`
  (для `body` — первым, для `section` — после эпиграфов) и `annotation` секции.
  Заодно `Fb2Normalizer` больше не включает `image` в порядок элементов секции
  — иначе сортировка сдвигала все иллюстрации в начало секции. Исправлено и в
  Pascal-порте (`fb2_parser.pas`, `fb2_writer.pas`, `fb2_normalizer.pas`).
  Проверено на книге из 525 иллюстраций: `normalize` → `rewrite` сохраняет все
  картинки в исходном порядке, в HTML — 525 `<img>` (было 1).
- **GUI: переход по ссылке «прыгал» к началу главы.** После клика по ссылке на
  сноску (или обратно в текст) вид сначала перемещался к сноске, а затем
  внезапно уезжал к началу текущей главы (в книге со сносками — к «Примечания»).
  Причина: `TFb2Outline` подсвечивает текущую главу программно
  (`Node.Selected := True`), но LCL `TTreeView` шлёт `OnChange` **отложенно** —
  `InternalSelectionChanged` включает таймер (1 мс), и только потом
  `ChangeTimer` вызывает `Change(Node)` → `OnChange`. Флаг `FUpdating` к этому
  моменту уже сброшен, поэтому `TreeChange` вызывал `GoToAnchor` и уводил вид к
  главе. Теперь дерево запоминает узел, выделенный программно
  (`FIgnoreChange`), и игнорирует ровно его `OnChange`.
- **GUI: навигация по оглавлению без перезагрузки документа.** `TFb2Viewer.GoToAnchor`
  теперь берёт Y якоря (`AnchorPosition`) и присваивает его `VScrollBarPosition`
  (движок внутри делает `ScrollTo(YPosition)` — ровно то же, что и `PositionTo`
  при переходе по `#anchor`), поэтому нет повторного разбора и раскладки HTML:
  переход мгновенный и без «мигания». Прежний путь (перезагрузка строки с
  `'#anchor'`) остался как фолбэк для якоря, которого нет в разобранном
  документе. Проверено на тестовой книге: `AnchorPosition('sec-2')=1127`,
  `GoToAnchor('sec-2')` → позиция `1127` (было `0`), текущая глава определяется
  верно; переход назад к `sec-1` и неизвестный якорь отрабатывают корректно.
- **GUI: возврат «из сноски в текст» уезжал в конец книги.** Причина —
  HtmlViewer неверно определяет Y у **инлайновых** якорей (`id` на `<a>`/`<span>`
  внутри абзаца): для них создаётся `TChPosObj`, `FindDocPos` не находит позицию
  и `ThtDocument.FindDocPos` возвращает `Len` (конец документа) — поэтому все
  обратные ссылки сносок вели в конец книги. Исправлено с двух сторон:
  (1) `fb2_html.pas` больше не вешает `id` на саму ссылку-сноску, а даёт
  **блочный** якорь абзацу с первой ссылкой на сноску (`<p id="noteref-nN">`) и
  ведёт обратные ссылки на него — блочные якоря HtmlViewer позиционирует
  корректно; (2) `TFb2Viewer` (`HandleInternalLink`) при клике по ссылке-сноске
  запоминает точную позицию чтения и при клике по обратной ссылке возвращает к
  ней (если позиция не запоминалась, переход делает движок по блочному якорю).
  Проверено на книге со 107 сносками: все обратные ссылки указывают на
  существующие блочные якоря (0 «висячих»); «из сноски 43 в текст» → y=19330
  (абзац со ссылкой), а не 56838 (конец); при предварительном клике по ссылке
  возврат точный (`saved=1087` → `back pos=1087`, `exact=TRUE`).

## [0.1.2] — 2026-10-04

Первая зафиксированная версия библиотеки.

### Добавлено
- **Разбор и запись FB2**: `Fb2Parser` (структуры по XSD FictionBook 2.0,
  идентификаторы глав) и `Fb2Writer` (сериализация, round-trip).
- **Валидация** по XSD — `Fb2Validator` (lxml), подробный отчёт об ошибках.
- **Нормализация/авто-исправление** — `Fb2Normalizer`: приведение к UTF-8,
  порядок элементов по XSD, обязательные поля, дубликаты `<binary>`,
  пробелы, битые ссылки на изображения, восстановление некорректного XML.
- **Конвертеры**: EPUB 2.0/3.0, DOCX, Markdown, HTML (в обе стороны);
  экспорт в TXT и PDF (reportlab).
- **Индекс библиотеки** — `Fb2Index` (SQLite): сбор, статистика, топ авторов,
  жанры, дубликаты, поиск по автору.
- **Перекодировка** — `Fb2Transcoder` (например, windows-1251 → UTF-8).
- **Переименование** — `FB2Renamer` и `FB2GroupRenamer` (шаблоны `${Al}`, `${Tt}`, …).
- **Сканеры** — авторов (`Fb2AuthorScanner`) и кодировок (`Fb2EncodingScanner`).
- **Разбиение и слияние** — `Fb2Splitter` (по главам, размеру, на N частей) и
  `Fb2Merger` (объединение метаданных, разрешение конфликтов `<binary>`).
- **Сетевые функции**: `Fb2MetadataFetcher` — обложки и аннотации из
  Open Library и Google Books (только стандартная библиотека);
  `WikipediaAuthor` — статья об авторе в Markdown.
- **CLI**: единая команда `pyfb2` (`fb2tools`, 13 подкоманд) и узкие
  console-scripts (`pyfb2-to-epub`, `pyfb2-validate`, …).
- **Инфраструктура**: `py.typed` (PEP 561), проверка типов mypy,
  сборка sdist/wheel, тесты (151), CI (ruff + pytest на Python 3.11–3.13).
- **Документация** (`doc/`) и **частичный порт на FreePascal** (`pas/`):
  структуры, парсер, writer, markdown.

### Изменено
- Версия берётся из `pyFB2.__version__` (единый источник, `dynamic` в pyproject).

### Исправлено
- `fb2_group_renamer`: файлы искались по одному имени вместо полного пути —
  групповое переименование работало лишь при совпадении рабочего каталога.
- `Fb2MetadataFetcher.save_cover`: путь без расширения теперь трактуется
  как каталог (раньше создавался файл с именем каталога).
- `strip_html`: `&nbsp;` не нормализовался (неверный порядок операций).
- Уточнены аннотации типов в парсере и конвертерах (mypy без замечаний).
